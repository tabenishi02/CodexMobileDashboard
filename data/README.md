# 表示用データとテストデータ

このディレクトリは、表示用JSONの形式確認、テスト用サンプル、ローカル動作確認用データの配置に使用します。

> [!NOTE]
> 確定したデータ仕様は`../docs/DATA_SCHEMA.md`、正常・異常サンプルは`samples/`にある。

## 用途の分離

リポジトリへ登録できるテストデータと、実際のCodexセッションから生成する実行時データを分離します。

```text
data/
├─ README.md           # 本書
├─ samples/            # 秘密情報を含まないテスト用JSON
└─ runtime/            # サンプル生成の一時出力（Git管理外）
```

- `samples/`には、架空または匿名化した小さなテストデータだけを置く。
- `runtime/`はサンプル生成やテストの一時出力だけに使用できる。
- PC収集ツールの実行時JSONは`%LOCALAPPDATA%\CodexMobileDashboard\data`へ保存する。
- Androidサーバー端末の本番データ保存先はINI設定で指定し、このリポジトリへ保存しない。
- PC側の処理位置、未送信キュー、認証トークンもリポジトリ外へ保存する。

`runtime/`は`.gitignore`で除外します。

## 表示用JSON

表示用データは役割ごとに分けます。

| JSON | 主な内容 |
|---|---|
| `dashboard.json` | 現在の作業、最新状態、エラー概要、次の作業 |
| `recent.json` | 直近2件のユーザー指示とCodex応答 |
| `messages.json` | ページ分割したセッションメッセージ、変更要約、会話上のファイル参照 |
| `errors.json` | 開発エラーと解決状況 |
| `decisions.json` | 採用、非採用、置き換え履歴を含む決定事項 |
| `files.json` | Git変更メタデータ |
| `metadata.json` | スキーマ、生成日時、収集状態、ハートビート |

Codexセッション由来の変更要約は、短い初期表示用要約と詳細を分離してPC側で生成します。Git差分本文やプロジェクトファイルは使用せず、未マスクのメッセージは要約材料にしません。全履歴は`messages/summaries/`へページ分割し、`messages.json`から参照します。

巨大な単一JSONは作成せず、メッセージのページや長文の断片には一意なファイル名または識別子を付けます。具体的なファイル名、フィールド、欠損値、スキーマバージョンはPhase 2のデータ設計で確定します。

## 共通データ方針

- JSONはBOMなしUTF-8、日本語非エスケープ、末尾LF付きで保存する。
- 日時はタイムゾーンを含むISO 8601形式とする。
- 各データに安定した一意なIDを付ける。
- ワークスペース、セッション、生成元を識別できるようにする。
- スキーマバージョンを記録する。
- 順序を持つデータには並び順または連番を記録する。
- 不明、未取得、空文字、空配列を区別する。
- JSON生成後のUTF-8バイト数を記録または検証できるようにする。
- 同じ送信データを重複保存しない識別情報を持たせる。
- 同じJSONLレコードの再読込はPC側で除外するが、別IDまたは別の出現順を持つ同文メッセージは削除しない。

## Git変更データ

`files.json`にはGitから取得したメタデータだけを含めます。

- ファイルパス
- 追加、修正、削除、名前変更、コピー、種類変更、競合、未追跡
- ステージ状態と作業ツリー状態
- 追加行数と削除行数
- 名前変更前後のパス
- バイナリーファイル判定
- ブランチ、`HEAD`、コミット識別情報

未追跡ファイルは内容を読み取らず、行数取得状態を`not_inspected`、バイナリ判定を`null`とします。空の追跡済みテキストファイルは`measured`かつ0行として区別します。取得失敗は`failed`として次の定期確認で再試行します。

次は含めません。

- プロジェクトファイル本体
- ソースコード本文
- Git差分本文
- 画像、動画、音声、PDFなどのファイル本体
- GitリポジトリやGitオブジェクト

## セッションテキスト

Codex JSONLから抽出対象としたテキストは、件数、文字数、保存期間を理由に削除・省略しません。Codex JSONL内にテキストとして記録されたコードブロックやコマンド出力は、セッション履歴の一部として扱います。

- 1データ断片は共通識別情報を含むJSON全体で最大256KiBとする。
- 一覧は100件または512KiBの早い方でページ分割する。
- 初期表示する最近のメッセージは50件または512KiBの早い方とする。
- 単一メッセージを分割する場合も、断片番号、総断片数、元のバイト数、検証値を保持する。
- 分割したメッセージを元の順序で完全に復元できるようにする。

## 秘密情報

サンプルと実行時データのどちらにも、次の秘密情報を意図的に含めません。

- 認証トークン
- APIキー
- パスワード
- 秘密鍵
- 認証情報を含むURL
- 秘密情報を含む環境変数

実データをサンプルへ転用しません。サンプルは最初から架空のプロジェクト名、パス、メッセージ、エラーで作成します。

Codexセッション本文は正規化直後にメモリ内で検査し、秘密情報を固定マーカーへ置換してから各抽出処理へ渡します。除外した秘密情報の原文、ハッシュ、長さをエラー表示、キャッシュ、ログへ残しません。

環境変数は秘密性の高い名前の値だけを対象にします。未知の長い文字列は長さだけでマスクせず、Git SHA、SHA-256、UUIDを維持します。MVPでは氏名、メールアドレス、電話番号、IPアドレスなど一般的な個人情報は自動マスクしません。

## 安全な保存

- 対象JSONと同じディレクトリの一時ファイルへ完全に書き込む。
- 置換前にUTF-8直列化と共通識別情報を検証する。
- `flush()`と`os.fsync()`の完了後に`os.replace()`で置換する。
- 書き込み・置換失敗時は一時ファイルを削除し、既存の正常なJSONを維持する。
- `metadata.json`を最後に置換し、複数ファイル更新中の不整合を`snapshot_id`で検出可能にする。
- 許可された保存先とファイル名以外へ書き込まない。
- パストラバーサルを拒否する。
- 同時読み書きによる途中データの配信を防ぐ。
- 容量不足時は過去データを自動削除せず、新規保存を停止して警告する。

## サンプルJSONの条件

Phase 2で作成するサンプルJSONは、次を満たすものとします。

- 実在するプロジェクトやユーザーの秘密情報を含まない。
- ユーザーとCodexのメッセージを区別できる。
- 日本語、絵文字、改行、コードブロックを含む。
- 正常、注意、エラーの状態を含む。
- Gitの追加、修正、削除、名前変更、コピー、種類変更、未追跡、バイナリ判定を含む。
- 空配列、欠損可能項目、長文、ページ境界をテストできる。
- ブラウザ表示とPython単体テストの両方で再利用できる。

不正JSON、欠損値、サイズ超過などの異常系データは、正常サンプルと区別できる場所へ配置します。

## Git管理

Gitへ登録するもの：

- `data/README.md`
- 架空または匿名化した`data/samples/`のテスト用データ

Gitへ登録しないもの：

- `data/runtime/`
- Codexセッションから生成した実行時JSON
- 処理済み位置情報
- 未送信キュー
- 一時ファイル
- 秘密情報を含むデータ

コミット前に`git status`と差分を確認し、実データが混入していないことを確認します。
