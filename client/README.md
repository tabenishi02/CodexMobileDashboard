# スマートフォン向け閲覧画面

このディレクトリには、Androidサーバー端末から配信し、閲覧スマートフォンのブラウザで使用するHTML、CSS、JavaScriptを配置します。

> [!IMPORTANT]
> Phase 5で固定HTML、モバイル向けCSS、JSON取得、ダッシュボード、作業ステータス、最終更新日時表示を追加しました。詳細画面の表示は後続タスクで実装します。

## 目的

スマートフォンを開発操作端末ではなく、現在の状況を短時間で確認して次の判断を行う端末として使用します。最初に概要を表示し、会話やエラーなどの詳細は必要な場合だけ読み込みます。

最終更新日時は`dashboard.json`の`generated_at`（PCが表示用データを生成した時刻）を使用し、Androidの受信日時やPCの最終確認日時とは混在させません。日時が欠けている場合も、閲覧端末の現在時刻で補完せず「日時不明」と表示します。

「次に行う作業」は`dashboard.json`の`next_actions`を受信順に表示します。表示文字列は各要素の`text`を使用し、作業がない場合は「次の作業はありません。」と表示します。

「最近の更新」画面は、開いた時に`recent.json`を取得します。応答中の`current_turn`を先頭に、完了済みの`turns`を新しい順に並べ、状態、開始・完了日時、ユーザーとCodexのプレビュー、ロールバック状態を表示します。

「チャット」画面は`messages.json`の最新ページを最初に取得し、「以前のメッセージを読み込む」で前ページを追加表示します。本文はHTMLとして解釈せず、テキストとして表示します。

チャット履歴では、ユーザーメッセージを「あなた」、Codexメッセージを「Codex」の役割ラベルで区別します。

「エラー」画面は、開いた時に`errors.json`を取得し、未解決を優先して重要度、状態、要約、最終発生日時、発生回数を表示します。

エラー一覧の詳細には`details_preview`を表示し、`detail_storage`が`inline`の場合は`details`もテキストとして表示します。

「決定事項」画面は、開いた時に`decisions.json`を取得し、表題、状態、決定日時、内容、理由を新しい順に表示します。

「ファイル」画面は、開いた時に`files.json`を取得し、パス、変更状態、追加・削除行数、ステージ状態だけを表示します。

変更ファイルの状態は「追加」「変更」「削除」などの日本語で表示し、変更行数は`+追加行数 / -削除行数`で表示します。

長文メッセージは`display_mode: collapsed`を受け取り、折りたたみを利用者が展開して本文を確認します。

チャット本文はCodex向けMarkdownサブセットとして表示します。markdown-it 14.1.0で解析し、DOMPurify 3.2.6で許可タグ・属性へサニタイズします。HTML・画像・埋め込みは非対応です。http/httpsリンクだけを新しいタブで開きます。highlight.js 11.11.1でコードをハイライトし、失敗時はプレーンテキストへフォールバックします。ライセンスは`../THIRD_PARTY_NOTICES.md`と`../licenses/`に保存し、外部CDNへは依存しません。

## 役割

- ダッシュボード概要の表示
- 現在の作業状態と最終更新日時の表示
- 最近の更新とチャット履歴の表示
- エラーと決定事項の表示
- Git変更メタデータの表示
- 次に行う作業の表示
- PCとAndroidサーバー端末の状態表示
- 通信中、データなし、通信失敗、古いデータの区別
- 手動更新と表示中の定期更新

## 行わない処理

- Codex JSONLの解析
- Gitコマンドの実行
- プロジェクトファイルの取得・編集
- Git差分本文の取得・表示
- 表示用データの要約・分類・再構成
- スマートフォンからのCodex操作
- Androidサーバー端末の設定変更

### ダッシュボード

最初に開く画面として、次の情報を短時間で確認できるようにします。

- プロジェクト名
- 現在の作業状態
- 最後のユーザー指示
- 最新のCodex回答
- 次に行う作業
- エラーの有無と重要度
- 変更ファイル数
- 現在のブランチ
- データ生成日時と最終受信日時
- PC収集ツールとAndroidサーバー端末の状態

### 詳細画面

- 最近の更新
- チャット履歴
- エラー一覧と詳細
- 決定事項一覧
- 変更ファイル一覧
- システム情報

Git画面にはファイルパス、変更状態、変更行数、ステージ状態、名前変更、バイナリ判定を表示します。プロジェクトファイル本体とGit差分本文は表示しません。

## 構成

```text
client/
├─ README.md           # 本書
├─ index.html          # 固定HTMLの画面骨格
├─ styles.css          # モバイル向けスタイル
├─ app.js              # 画面初期化とJSON取得（画面更新は実装予定）
└─ tests/              # JSON取得・表示ロジックのテスト
```

HTML、CSS、JavaScriptは分離し、外部ライブラリやCDNには依存しません。ファイル構成は実装時に必要性を確認し、不要な分割は行いません。

## データ取得

画面はAndroidサーバー端末から、役割ごとに分割されたJSONをHTTPS GETで取得します。閲覧スマートフォンにはプライベートCAの公開証明書を信頼させ、証明書エラーを無視して接続する運用は行いません。

公開JSONのURLは`/data/{workspace_id}/{relative_json_path}`である。例として概要は`/data/{workspace_id}/dashboard.json`、会話ページは`messages.json`内の索引が示す`messages/pages/...json`から取得する。未commitのstaging Snapshotへはアクセスできない。

```text
dashboard.json
recent.json
messages.json
errors.json
decisions.json
files.json
metadata.json
```

複数ワークスペースを扱う一方、現行サーバーにはworkspace一覧APIがない。画面はURLクエリの`workspace_id`を使用する。閲覧URLは`/?workspace_id=<workspace_id>`とし、未指定時はIDを推測せず指定を案内する。URLパス方式と一覧APIはMVP後の拡張候補とする。詳細は[`../docs/PHASE5_HANDOFF.md`](../docs/PHASE5_HANDOFF.md)を参照する。

- 初期表示では`dashboard.json`、`metadata.json`、`/health?workspace_id=<workspace_id>`を並行取得し、ETagと`304 Not Modified`をメモリ内キャッシュで扱う。
- 会話全文などの詳細は、画面を開いたときにページ単位で取得する。
- 一覧は100件または512KiBの早い方でページ分割する。
- 長文メッセージは断片を順番に取得して復元する。
- JSONが欠損または不正な場合は、画面全体を停止せず対象部分にエラーを表示する。

JSON取得中は、初期表示と各詳細画面に「読み込んでいます」を表示し、アプリ本体へ`aria-busy="true"`を設定します。

「更新」ボタンは、概要・メタデータ・サーバー状態をETag付きで再取得し、表示を更新します。取得中はボタンを無効化します。

ブラウザが表示中のときは15秒間隔で初期データをETag付きで再取得します。非表示中は自動取得しません。

画面を非表示にすると自動更新タイマーを停止し、再表示時は即時更新してから15秒間隔の更新を再開します。

## 更新動作

| ブラウザ状態 | 動作 |
|---|---|
| 画面表示中 | 15秒ごとに更新確認 |
| 別タブ、画面消灯、バックグラウンド | 自動更新停止 |
| 画面へ復帰 | 即時更新後、15秒間隔を再開 |
| 手動操作 | 更新ボタンで即時更新 |

ETagと`If-None-Match`を使用し、変更がない場合は`304 Not Modified`を受け取ってJSON本文を再取得しません。同じ時刻に複数の更新処理を重複実行しないようにします。

## モバイル表示

- 一般的なAndroidスマートフォンの縦画面を基準にする。
- 重要な概要を画面上部へ配置する。
- 長文、コードブロック、エラー詳細は折りたたむ。
- タップ領域を十分に確保する。
- 本文の横スクロールを避ける。
- コードなど折り返しが不適切な内容だけ、要素内で横スクロールを許可する。
- 文字サイズをブラウザの設定で拡大できるようにする。
- 色だけに依存せず、文字とアイコンでも状態を示す。
- 通信中と操作可能な状態を区別する。

## セキュリティ

- JSON内の文字列は原則としてテキストとして挿入する。
- セッション由来のHTMLをそのまま`innerHTML`へ渡さない。
- コードブロックやコマンドも実行せず文字列として表示する。
- 外部スクリプトと外部スタイルを読み込まない。
- 認証トークンや秘密情報をHTML、JavaScript、ブラウザ保存領域へ埋め込まない。
- エラー画面へ内部パス、Traceback、トークンを表示しない。
- 将来Markdown表示を導入する場合は、HTML混入とスクリプト実行を防ぐ方法を先に決定する。

空配列などデータがない場合は、取得失敗と区別して「データがありません（対象）」と表示します。

通信失敗または不正なJSON応答時は、空データと区別して対象画面に失敗理由を表示します。

JSON構文または構造が不正な場合は「JSONデータが不正です」と表示し、通信失敗と区別します。

`dashboard.generated_at`から閲覧端末時刻まで10分を超えた場合は「データが古い可能性があります」と警告します。日時不正・未取得時は断定しません。

## 状態表示

次の日時を区別して表示します。

- PCが表示用データを生成した日時
- Androidサーバー端末が受信した日時（`/health?workspace_id=<workspace_id>`の`last_received_at`）
- PC収集ツールが最後に確認した日時
- 内容が最後に変わった日時
- 公開中Snapshot ID（`/health?workspace_id=<workspace_id>`の`current_snapshot_id`。システム情報画面に表示する）

これにより「変更がない状態」と「PC収集ツールまたは通信が停止した状態」を区別します。Androidサーバー端末の詳細エラーは表示せず、正常、注意、異常、更新停止などの簡潔な状態だけを表示します。

## 対応確認

- Androidブラウザで主要画面を確認する。
- 一般的なAndroidスマートフォン相当の画面幅で確認する。
- 基準端末の検証用Android端末はサーバーとして使用し、別の閲覧スマートフォンから一連動作を確認する。
- JavaScript無効時は、利用にJavaScriptが必要であることを表示する。
- 読み込み中、空データ、不正JSON、通信失敗、古いデータをそれぞれテストする。
