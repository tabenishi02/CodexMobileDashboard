# 作業用PC側の収集・変換・送信ツール

このディレクトリには、作業用PCでCodexセッションとGit状態を収集し、スマートフォン表示用JSONへ変換してAndroidサーバー端末へ送信するツールを配置します。

> [!IMPORTANT]
> Codex JSONLの探索・索引化・差分更新、既知形式のメモリ内正規化、秘密情報除外、各情報の抽出、Git変更メタデータ取得、変更要約生成、表示用JSONへのメモリ内変換と原子的なUTF-8保存、HTTPS送信、失敗Snapshotの保持と再送を実装済みです。これらをまとめて実行するcollector本体は未実装です。

## 役割

作業用PCをシステムの処理主体とし、次を担当します。

- 許可ルート内の対象ワークスペースとCodexセッションの自動検出・検証
- Codex JSONLの追加部分の読み取り
- ユーザーとCodexのメッセージ抽出
- 現在の作業状況、エラー、決定事項、次の作業の抽出
- Codexセッションに基づく変更内容の要約
- Git変更メタデータの取得
- 表示用JSONへの分類と変換
- 秘密情報の除外
- 大容量テキストの分割（実装済み）
- UTF-8 JSONの安全なローカル保存
- Androidサーバー端末への認証付きHTTPS POST
- 送信失敗時の保持・再試行
- 処理位置、送信状態、ハートビートの管理
- 収集・変換・送信ログの出力

## 情報源

### Codex JSONL

Codex JSONLを、会話と作業文脈の情報源として使用します。

- ユーザーの指示
- Codexの回答
- ツール実行結果
- 現在の作業内容
- エラー
- 決定事項
- 次に行う作業
- 変更内容の意味を表す要約

JSONLは読み取り専用で扱い、変更、移動、削除を行いません。前回処理位置以降の追加部分だけを読み、再起動後も続きから処理します。

### Git

Gitを、実際の変更ファイルと変更状態の正とします。

- ファイルパス
- 追加、修正、削除、名前変更、コピー、種類変更、競合、未追跡
- ステージ状態と作業ツリー状態
- 追加行数と削除行数
- バイナリーファイル判定
- ブランチ、`HEAD`、コミット識別情報

プロジェクトファイル本体とGit差分本文は収集・送信しません。変更内容のセマンティックな要約にもGit差分本文を使用しません。

## 行わない処理

- 対象プロジェクトでの`git init`や初回コミット
- Gitの所有権、ロック、競合、履歴の自動修正
- プロジェクトファイルのコピーと送信
- Git差分本文の取得・送信・要約
- Codex JSONLの書き換え
- Androidサーバー端末の設定変更
- スマートフォン表示用HTMLの生成
- 外部クラウドサービスへの送信

## 予定構成

実装時点で責務の分離が必要かを確認し、最初から過剰にファイルやクラスを増やしません。

```text
tools/
├─ README.md           # 本書
├─ collector.py        # 未送信キューの手動確認・再送コマンド
├─ session_reader.py   # Codex JSONLの探索・索引化・差分読み取り
├─ record_normalizer.py # 既知のログ形式をメモリ内の共通形式へ正規化
├─ secret_redactor.py # 正規化本文から認証秘密を固定マーカーへ置換
├─ record_deduplicator.py # 再読込された同一レコードを除外
├─ collector_state.py # JSONL読取位置と重複排除状態を原子的に保存
├─ incremental_collector.py # 追記分の読取・正規化・秘密情報除外・重複排除を接続
├─ logging_setup.py # コンポーネント別の安全な日次ローテーションログを設定
├─ https_sender.py # 検証済みHTTPSでSnapshotを送信・commit
├─ pending_snapshot_queue.py # 失敗Snapshotの本文とDelivery IDを永続保存
├─ chat_extractor.py   # 会話、ツール概要、開発者指示を抽出
├─ work_status_extractor.py # Codex状態とターン進行を抽出
├─ next_task_extractor.py # 明示された次タスクの抽出とCodex CLIによる推定
├─ error_extractor.py # 開発エラーの抽出、重複集約、自動解決
├─ decision_extractor.py # ユーザーが確定した決定事項と更新履歴の抽出
├─ file_reference_extractor.py # 会話上のファイル参照を安全なメタデータへ変換
├─ git_change_collector.py # Gitの変更状態・行数・セッション中コミットを収集
├─ change_summary_generator.py # マスク済みCodexセッションからターン別変更要約を生成
├─ json_converter.py # 抽出結果から表示用JSON文書一式をメモリ内生成
├─ json_writer.py # 表示用JSON文書一式をBOMなしUTF-8で保存
└─ tests/              # PC側処理の単体テスト
```

処理が大きくなった場合だけ、JSONL読み取り、Git取得、JSON生成、HTTP送信を個別モジュールへ分割します。

## 手動実行

`python -m tools.collector --config <collector.ini> queue-status`で未送信キューの安全な要約を確認できる。`retry-queued`は最古の1件、`retry-queued --all`は成功する限り全件を順に再送する。Windows タスク スケジューラには、再送専用の定期実行を登録できる。現時点ではJSONL収集・変換をまとめて実行する手動コマンドは未実装である。詳細は[`../docs/MANUAL_COMMAND.md`](../docs/MANUAL_COMMAND.md)と[`../docs/SCHEDULED_EXECUTION.md`](../docs/SCHEDULED_EXECUTION.md)を参照する。

## 実装済みのJSONL読み取り

`session_reader.py`は次を提供します。

- `sessions`と`archived_sessions`にある全`rollout-*.jsonl`の再帰探索
- UTF-8 JSONLの完全な行だけを対象にした逐次読み取り
- バイトオフセットと物理行番号を指定した差分読み取り
- 書き込み途中の末尾行の保留
- 不正な中間行と未知レコードの警告・除外
- ファイル短縮時の先頭からの再解析
- `session_meta`、`turn_context`からのワークスペース候補取得
- セッションIDによるライブ／アーカイブファイルの同一視
- 最終イベント日時に基づく同一セッション内の現行ファイル選択

この段階ではワークスペース候補のGit検証やメッセージ本文の抽出を行わない。読み取ったレコードを後続処理へ渡し、許可されたワークスペースのターンだけを抽出する。

## 実装済みの差分更新

`incremental_collector.py`は、セッションごとの保存済み読取位置から完全な追加行だけを読み、正規化、秘密情報除外、重複排除を順に適用します。

- 追記時は前回のバイト位置・行番号から続け、短縮・置換・移動時は既存の検証規則に従って安全に先頭から再解析します。
- 不完全な末尾行は次回まで保留し、処理位置に含めません。
- 秘密情報を除外したレコードだけを重複判定と後続処理へ渡します。
- 結果の`next_state`は候補として返すだけで、同じ収集周期の抽出、JSON変換、保存が成功するまでファイルへ書き込みません。これにより途中失敗で読取位置だけが進むことを防ぎます。

## 実装済みの形式正規化

`record_normalizer.py`は、読み取ったレコードをファイルへ保存せず、メモリ内の`NormalizedRecord`へ変換する。

- `response_item.message`と`event_msg`の会話イベントを、出典を区別した共通メッセージ形式へ変換する。
- メッセージID、phase、turn IDなどがない場合は推測せず`None`とする。
- 文字列または配列で記録されるツール結果を、順序付きの共通本文要素へ変換する。
- ターン開始・完了・中断、設定、トークン使用量、パッチ、Web検索、MCP完了を共通分類へ変換する。
- ISO 8601日時をタイムゾーン付き表現へ揃え、不正な日時は現在時刻で補完しない。
- 未知の下位形式は本文を推測せず、位置と種別だけを警告して除外する。
- 画像本体、Git差分本文、ファイル本文、基礎指示、暗号化推論、MCP引数・結果本文を正規化レコードへ複製しない。

同じ会話の重複判定はこの層では行わない。`response_item`と`event_msg`の出典を残し、後続のメッセージ抽出処理で`response_item`を優先して確定する。異常終了時は永続化済みの読み取り位置より後を元JSONLから再処理する。

## 実装済みのチャット抽出

`chat_extractor.py`は、正規化レコードからセッション内の表示順を維持したメッセージ列を生成する。

- 会話本文は`response_item.message`を正とし、対応する`event_msg`は二重登録しない。
- `response_item`がない会話イベントだけを代替メッセージとして使用する。
- 同じ本文をユーザーまたはCodexが意図的に複数回送った場合は削除しない。
- ネイティブIDがない場合は、セッションID、情報種別、元レコード位置から決定的な代替IDを生成する。
- Codexの`commentary`と`final_answer`を両方保持し、`commentary`を折りたたみ指定にする。
- ツール名、呼び出しID、結果受信、判定可能な成否・処理時間だけを概要として保持し、引数と出力本文を複製しない。
- 開発者指示は折りたたみ指定にし、セッション内で完全一致する本文は最初の1件だけ保持する。再出現位置には元メッセージIDへの参照を置き、初回メッセージに総出現回数を保持する。
- メッセージ先頭の完全な`recommended_plugins`、AGENTS指示、`environment_context`だけを自動付加情報として除外する。不完全な構造や先頭以外の例示は保持する。
- 自動付加情報だけのメッセージは表示せず、元位置と除外した種類だけを監査用情報としてメモリ内に保持する。

チャット抽出結果も中間ファイルへ保存しない。秘密情報は正規化直後かつチャット抽出前にマスクする。コードブロック分割、長文分割、表示用JSON生成が成功するまで読み取り位置を確定しない。

## 実装済みの作業状況抽出

`work_status_extractor.py`は、ターンイベントと抽出済みチャットを関連付けて現在状態を判定する。

- 終了イベントのない最新`task_started`を`working`とする。
- `task_complete`または`turn_aborted`で進行中ターンがなくなった状態を`idle`とする。
- ターンイベントが一つもなければ`unknown`とする。
- `stopped`は過去ログだけから判定せず、後続のcollector稼働監視で設定する。
- `turn_aborted`はターン状態`failed`とし、理由があれば保持する。
- 新しいターン開始時に古い未完了ターンが残っていれば、明示的な失敗と断定せず`incomplete`、理由を`superseded_by_new_turn`として警告する。
- `thread_rolled_back`の対象ターンは削除せず、`rolled_back`を付けて通常の最新ターン判定から除外する。
- 作業中ターンと同じturn IDのユーザー指示を`current_work`の根拠とし、表示用プレビューを最大500文字で生成する。全文はメッセージ履歴に保持する。
- 開始・完了のUnixミリ秒をUTCのタイムゾーン付きISO 8601へ変換し、欠損時はレコード日時を使用する。各日時に`event_field`、`record_timestamp`、`missing`の取得元を付け、補完の有無を判別可能にする。

作業状況の抽出結果もメモリ内だけで扱い、秘密情報除外と表示用JSON生成が成功するまで読み取り位置を確定しない。

## 実装済みの次タスク抽出

`next_task_extractor.py`は、最新2ターンとして選択されたメッセージから次に行う作業を1件決定する。

- 「次のタスクは…」「次に行う作業：…」などの明示表現を最優先し、根拠メッセージIDを保持する。
- 明示がなければ、現在のCodex CLIログインを再利用して非対話モードで推定する。
- CLIは一時ディレクトリを作業場所とし、`--ephemeral`、`--sandbox read-only`、`--ignore-user-config`、`--ignore-rules`を使用する。対象プロジェクトを作業ディレクトリにせず、MCPやプラグインを含むユーザー設定を読み込まない。
- CLIへ渡すのは秘密情報除外済みと明示された現在状況、最新2ターン、決定事項、未完了タスクだけとする。未マスク入力ではCLIを起動しない。
- 推定入力全体をUTF-8で128KiB以内にし、省略は推定用コンテキストだけに限定して警告を残す。元の履歴は変更しない。
- タイムアウトは120秒、即時再試行は0回とする。同じ根拠の成功結果は再利用し、失敗時のタスクリスト補完結果は5分間再利用する。
- CLIの終了コード、タイムアウト、構造化JSONを検証し、失敗時は`TASKS.md`の先頭の未完了項目へフォールバックする。
- CLIの標準エラー、プロンプト、会話本文を運用ログへ出力しない。

次タスク推定には`secret_redactor.py`の安全化済み結果だけを渡し、未マスクの会話ではCodex CLIを起動しない。

## 実装済みの開発エラー抽出

`error_extractor.py`は正規化レコード、抽出済みツール概要、ターン状態を関連付け、明示的な失敗と限定した既知形式を開発エラーへ変換する。

- 非ゼロ終了コード、パッチ失敗、MCP失敗、Python Traceback、`unittest`失敗、Git `fatal`、ターン中断を対象とする。
- 終了コード0の標準エラーだけでは登録せず、Tracebackまたはテスト失敗を認識できる場合だけ警告にする。
- エラーを分離できる場合はその部分を保持し、分離できない複合出力は最大4,000文字のプレビューだけにする。正常出力やツール出力全文は複製しない。
- 同一セッション内で、安全な処理識別情報から同じと確認できた失敗だけを集約し、初回・最終日時と発生回数を保持する。
- 同じ処理の後続成功だけで自動解決する。安全な処理識別情報がなければ、異なる呼び出しを推測で統合・解決しない。
- ロールバック済みエラーは履歴に保持するが、現在の未解決件数から除外できる印を付ける。
- 日時はレコード日時、ファイル更新日時の順で使用し、取得不能時は`null`と`missing`を保持する。
- エラー詳細と処理入力は運用ログへ出力せず、秘密情報除外と表示用JSON生成までメモリ内だけで扱う。

## 実装済みの決定事項抽出

`decision_extractor.py`は、全セッションの抽出済みチャットを日時順に受け取り、ユーザーが確定した決定だけをワークスペース単位の履歴へ変換する。

- 自己完結した採用、拒否、変更、撤回はPC側の明示規則で抽出する。
- 「案A」「提案をそのまま」などの参照表現は、マスク済みのユーザーメッセージと直前のCodexメッセージだけを隔離したCodex CLIで解決する。
- Codexの提案だけ、質問、検討中、一時的な実装判断は決定にしない。CLI失敗時も決定を推測しない。
- 1メッセージ内の独立した項目は別々の決定にする。
- 同じ決定の再確認は根拠セッション・メッセージを追加し、内容変更は旧決定を残して相互参照で置き換える。
- 過去の内容へ戻した場合も新しい履歴イベントとして扱う。
- 理由は会話に存在する場合だけ保存し、日時はメッセージ日時、ファイル更新日時、欠損の順で出典を明示する。
- CLI入力は最大128KiB、タイムアウト120秒とし、同じ成功入力は稼働中のrunnerで再利用する。

参照解決が必要な決定には`secret_redactor.py`の安全化済み本文だけを使用し、未マスク本文では警告付きで保留してCLIへ渡さない。

## 実装済みのファイル参照抽出

`file_reference_extractor.py`は表示対象のユーザー・Codexメッセージから、会話で明示されたファイル参照だけを抽出する。

- ユーザー添付ブロック、Markdownローカルリンク、インラインコード、通常文の絶対・相対パスと一般的なファイル名を対象にする。
- ツール・開発者メッセージ、URL、フェンス付きコードブロックは対象外にする。
- ワークスペース内は解決後の親子関係を検証して相対パスへ変換する。
- ワークスペース外は絶対パスを破棄し、ファイル名、拡張子、存在種別だけを保持する。外部パスのハッシュも送信IDに使わない。
- ファイル本文を開かず、`file`、`directory`、`missing`、`unknown`だけを判定する。UNCは存在確認しない。
- 同じワークスペース相対パスを集約し、セッション、メッセージ、行、列、参照形式を保持する。外部同名ファイルはメッセージごとに分離する。
- Git変更とは混同せず、後続の表示用JSON変換で各メッセージの`file_references`へ関連付ける。

## 実装済みのGit変更メタデータ取得

`git_change_collector.py`はGitを実際の変更状態の正として、ファイル本文と差分本文を返さずにメタデータを収集する。

- リポジトリルートと`HEAD`を検証し、ブランチと現在の作業ツリーを取得する。
- ステージ、未ステージ、未追跡、競合、名前変更、コピー、種類変更をNUL区切り出力から解析する。
- JSONLの開始コミットを優先し、現在の`HEAD`の祖先と確認できた場合だけセッション中のコミット済み変更を取得する。
- 行数は`measured`、`binary`、`not_inspected`、`not_applicable`、`failed`を区別し、空ファイルの0行と未調査の`null`を混同しない。
- 未追跡ファイルの内容は調べず、バイナリ判定も`null`にする。サブモジュール内部は再帰収集しない。
- 一部のGitコマンドが失敗しても取得済み状態を保持し、再試行が必要な警告を返す。
- `change_id`はワークスペースIDと正規化済み相対パスのSHA-256とし、日時は含めない。

## 実装済みの秘密情報除外

`secret_redactor.py`は正規化直後の各本文要素をメモリ内で安全化し、その結果だけをチャット、作業状況、エラー、決定事項、次タスク、変更要約の抽出へ渡す。

- APIキー、トークン、パスワード、PEM秘密鍵、URL userinfoを固定マーカーへ置換する。
- `Authorization`ヘッダー、秘密名への代入、JSON秘密フィールド、コマンドオプション、既知のAPIキー・トークン形式を検出する。
- 環境変数は`API_KEY`、`TOKEN`、`PASSWORD`、`SECRET`、`PRIVATE_KEY`など秘密性の高い末尾名を持つ値だけを対象にする。
- 既存の`[REDACTED:...]`は維持し、二重マスクしない。
- Git SHA、SHA-256、UUID、一般的な長い識別子は、秘密名や認証文脈がなければマスクしない。
- MVPでは氏名、メールアドレス、電話番号、IPアドレスなど一般的な個人情報を自動検出しない。
- マスク前の値、ハッシュ、長さを結果・キャッシュ・ログに保持しない。ログは件数と種別だけを記録する。
- JSON変換時はマスク種別と検出方法を、本文分割後の実際の`block_id`へ関連付ける。

## 実装済みのレコード重複排除

`record_deduplicator.py`は秘密情報除外直後に実行し、JSONLの再読込やアーカイブ移動で同じレコードが再登場しても後続処理へ重複して渡さない。

- ネイティブIDがある場合は、セッションとレコード形式を含む決定的な識別子を使用する。
- ネイティブIDがない場合は、安全化済み内容のフィンガープリントと同一内容の出現順を使用する。
- 同じ本文でも別IDまたは別の出現順なら、意図的な反復として保持する。
- 未マスク入力はフィンガープリント作成前に拒否する。
- セッションごとの読取位置と重複判定状態は`collector-state.json`へ原子的に保存する。

## 実装済みの前回処理位置保存

`collector_state.py`は`%LOCALAPPDATA%\CodexMobileDashboard\state\collector-state.json`へ、セッションIDごとの最後に読んだ完全行のバイト位置・行番号・先頭部分のSHA-256・重複排除状態を保存する。

- JSONLに追記された場合は保存済み位置から続けて読む。
- `sessions`から`archived_sessions`へ移動しても、保存済み部分が一致すれば同じ位置から再開する。
- ファイル短縮・置換・状態ファイル破損を検出した場合は、状態を推測せず先頭から再解析または起動失敗とする。
- 保存失敗時は既存の正常な状態ファイルを保持する。

## 実装済みの変更要約生成

`change_summary_generator.py`は秘密情報除外済みのCodexセッション情報だけを使用し、終端状態のターンごとに短文と詳細を分けた変更要約を生成する。

- JSONLのネイティブ`turn_id`を優先し、欠損時は既存の決定的な代替IDを使う。由来を`turn_id_source`に保持する。
- Codex最終回答、ユーザー指示、途中経過、ツール概要、ファイル参照に異なる根拠強度を設定する。
- 具体的な最終回答は規則で抽出し、曖昧な場合だけ隔離したCodex CLIへ渡す。
- CLI入力は最大128KiB、タイムアウト120秒、即時再試行なしとし、成功を再利用、失敗を5分間キャッシュする。
- CLIが入力外の根拠メッセージIDを返した場合は要約を採用しない。
- CLI失敗時はユーザー指示や以前の要約から成果を推測せず、明示結果がなければ要約なしの警告にする。
- 失敗・記録不完全を完了と断定せず、ロールバック済み要約は履歴に保持する。応答中は要約しない。
- 未マスク入力は規則抽出にもCLIにも使用せず、原文やそのハッシュをキャッシュしない。

## 処理の流れ

```text
設定と秘密ファイルを検証
  ↓
JSONLからワークスペース候補を抽出
  ↓
許可ルート内のGitワークスペースだけを登録・検証
  ↓
Codexセッションと前回処理位置を確認
  ↓
JSONLの追加部分を読み取って正規化
  ↓
正規化本文から秘密情報を除外
  ↓
安全化済みレコードの重複を除外
  ↓
安全化済み情報を分類・抽出
  ↓
Git変更メタデータを取得
  ↓
表示用JSONを生成してUTF-8バイト数で分割
  ↓
一時ファイルへ保存して原子的に置換
  ↓
変更されたデータだけを認証付きHTTPS POST
  ↓
処理位置と送信結果を保存
```

各段階で失敗した場合は、既存の正常な出力と処理位置を不用意に進めません。

## 設定

通常設定はUTF-8のINIファイルで管理し、Python標準の`configparser`で読み取ります。

主な設定項目：

- 自動検出を許可するワークスペースルート
- Codexセッションの保存場所
- Androidサーバー端末のHTTPS送信先URLとCA証明書
- ローカル出力先
- 接続・読み取りタイムアウト
- 送信分割サイズ
- 作業中・停止中の確認間隔
- ハートビート間隔
- ログ出力先とログレベル

PC側は1つの共通INIを使用します。JSONLの`cwd`等から候補を抽出し、`C:\codex`配下でGitと初回コミットを確認できたリポジトリだけを自動登録します。一時的に添付・参照した許可ルート外のファイルは、ワークスペース登録の根拠にしません。

設定、秘密、状態、未送信キュー、生成JSON、ログは`%LOCALAPPDATA%\CodexMobileDashboard`配下へ用途別に保存します。認証トークンはINIへ直接記載せず、秘密ファイルから読み取ります。必須設定、秘密ファイル、CA証明書が不正な場合は、安全のため処理を開始しません。`recent.json`の完了済みターン数は設定項目にせず2件に固定します。

## 更新タイミング

| 状態 | 動作 |
|---|---|
| Codexのターン完了 | 即時収集・変換し、変更時に送信 |
| Codex作業中 | 30秒ごとに追加データとGit状態を確認 |
| Codex停止中 | 60秒ごとに追加データとGit状態を確認 |
| 正常な送信が5分間ない | 小さなハートビートを送信 |

同じデータを重複生成・送信せず、内容が変わっていない場合は通常JSONを再送しません。

## データ量と分割

- 分割判定はJSON生成後のUTF-8バイト数で行う。
- 1データ断片はJSON全体で最大256KiBとする。
- 1 HTTPリクエストは最大1MiBとする。
- 通常は約800KiBで次のリクエストへ分ける。
- 一覧は100件または512KiBの早い方でページ分割する。
- 単一メッセージのJSON表現が256KiBを超えた場合、UTF-8文字境界で`messages/chunks/`へ分割する。
- ブロックID、種別、コード言語、断片番号、総数、UTF-8サイズ、SHA-256を保持し、元の内容を復元できる。
- 対象テキストを件数、文字数、保存期間を理由に削除・省略しない。

## 実装済みの表示用JSON変換

`json_converter.py`は、秘密情報除外済みと確認された抽出結果だけを受け取り、同じ`snapshot_id`と`generated_at`を持つ表示用JSON文書一式をメモリ内で生成する。

- `dashboard.json`、`recent.json`、`errors.json`、`decisions.json`、`files.json`、`metadata.json`を生成する。
- メッセージは100件または512KiBの早い方で`messages/pages/`へ分割する。
- 全変更要約は同じ基準で`messages/summaries/`へ分割し、`messages.json`に索引を置く。
- 通常文と正常なフェンス付きコードブロックをPC側で分離し、壊れたフェンスは本文全体を通常文として保持する。
- 各ページのUTF-8バイト数とSHA-256をメモリ内の決定的なUTF-8表現から算出する。
- 未マスク入力は文書を生成せず`UnsafeJsonInputError`で停止する。
- `json_converter.py`自体はファイルを書き込まず、保存は`json_writer.py`へ分離する。

## 実装済みのUTF-8 JSON保存

`json_writer.py`は`JsonSnapshot`を設定の`output_dir`配下にある`<workspace_id>/`へ保存する。

- `encode_json()`が返すBOMなしUTF-8、日本語非エスケープ、末尾LF付きのバイト列をそのまま書き込む。
- 保存結果として相対パス、UTF-8バイト数、SHA-256を返す。
- 絶対パス、`..`、バックスラッシュ、JSON以外の拡張子、Windowsで同一になる重複パスを保存前に拒否する。
- 全文書のスキーマ、スナップショット、生成日時、ワークスペース、セッション識別情報が一致することを保存前に確認する。
- 対象JSONと同じディレクトリに推測困難な名前の一時ファイルを作成し、全バイトを書き込む。
- `flush()`と`os.fsync()`の完了後に`os.replace()`でファイル単位に原子的置換する。
- 置換失敗時は一時ファイルを削除し、置換前の既存ファイルを維持する。
- 複数ファイル全体は単一トランザクションにできないため、設計済みの更新順序を守り、`metadata.json`を最後に置換する。途中状態は`snapshot_id`不一致として検出できる。

## HTTPS送信

- Python標準ライブラリでHTTPS POSTする。
- プライベートCAの公開証明書を設定し、サーバー証明書と接続先IPアドレスまたはホスト名を検証する。
- 証明書検証を無効化しない。
- 接続と読み取りにタイムアウトを設定する。
- データごとに一意な送信識別子を付ける。
- HTTPステータスと応答形式を検証する。
- 一時的な失敗は初回を含めて最大5回、1、2、4、8秒の指数バックオフで再試行する。HTTP 429の`Retry-After`は待機時間より優先する。
- 恒久的なHTTPエラーは短時間で自動再試行しない。
- 送信に失敗したデータは、受信成功が確認できるまでPC側に保持する。
- ファイルは相対パス昇順に`POST /api/v1/snapshots/{workspace_id}/{snapshot_id}/{relative_json_path}`へ送信し、すべて`stored`の応答を確認した後だけcommit APIを呼び出す。
- 各送信はBearer TokenとUUIDの`X-Delivery-Id`を使用する。再送では同じDelivery IDを使い、Token・本文・応答本文をログに出力しない。
- Androidサーバー端末はcommitの受理時だけstagingのSnapshotを公開する。`metadata.json`の受信を公開境界にはしない。
- 最終送信失敗はqueue_dirへ原子的に保存し、commit成功後だけ削除する。キューは全ワークスペースのsequence順で再送し、本文・Delivery ID・SHA-256を保持する。

平文HTTPは、実セッション、Git状態、本番トークンを使用しない独立したサンプル疎通確認だけに限定します。通常のcollectorは`http://`の送信先を拒否します。

## 安全な実装

- Python 3.10以上で動作する構文と標準ライブラリを使用する。
- Gitコマンドは`subprocess.run()`へ引数リストで渡す。
- `shell=True`を使用しない。
- ワークスペースやファイルパスをコマンド文字列へ連結しない。
- Git出力の終了コードと標準エラーを確認する。
- NUL区切りのGit出力は必要に応じてバイト列のまま解析する。
- JSONは一時ファイルへ書き込んでから原子的に置換する。
- APIキー、トークン、パスワード、秘密鍵を出力・送信・ログ記録しない。
- チャット全文、コード全文、HTTP本文を運用ログへ出力しない。

## ログ

次の処理ごとに、コンソールとUTF-8テキストログへ記録します。

- `collector`：Codex JSONLの検出と読み取り
- `converter`：抽出、分類、JSON生成
- `git`：Git状態と変更メタデータの取得
- `sender`：Androidサーバー端末へのHTTPS送信

通常運用は`INFO`以上とし、日単位でローテーションして直近7日分を保持します。秘密情報と大量の本文は記録しません。

`logging_setup.py`は`collector`、`converter`、`sender`にUTF-8の日次ローテーションファイルとコンソール出力を設定します。差分更新ではセッションID、処理件数、重複数、マスク件数、警告件数だけを記録し、会話本文、秘密値、本文のハッシュや長さは出力しません。

## テスト観点

- 採用済みの実JSONLを欠落・重複なく処理できる。
- 収集ツール再起動後に続きから処理できる。
- JSONLの移動、短縮、不完全な末尾行を処理できる。
- Gitの追加、修正、削除、名前変更、コピー、種類変更、競合、未追跡を区別できる。
- プロジェクトファイルとGit差分本文を送信データへ含めない。
- 日本語、絵文字、改行、長文を保持できる。
- 256KiBを超えるメッセージを分割・復元できる。
- 通信失敗後に未送信データを保持し、復旧後に重複なく再送できる。
- 秘密情報を送信データとログから除外できる。
