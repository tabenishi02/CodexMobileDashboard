# Androidサーバー端末の要件と基準端末の確認結果

## 対象範囲

サーバー対象は、Termuxを利用でき、次の条件を満たすAndroidスマートフォンとする。

- Python 3.10以上を利用できる。
- Python標準ライブラリのサーバーを実行し、指定ポートへbindできる。
- `ssl.SSLContext`を利用でき、プライベートCAが発行した証明書でHTTPSを提供できる。
- 作業用PCと閲覧スマートフォンからネットワーク接続できる。
- JSONとログを保存できる空き容量がある。
- Termuxのアプリ専用領域を使用できる。
- バッテリー最適化やメーカー独自の省電力制御を調整し、必要なバックグラウンド動作を継続できる。

特定メーカーやCPUアーキテクチャには依存しない。以下は動作確認済みの基準端末である検証用Android端末の実測結果であり、サーバー対象をAndroid端末に限定するものではない。

## パス

Termuxホーム：

```text
/data/data/com.termux/files/home
```

ダッシュボード配置先：

```text
/data/data/com.termux/files/home/CodexMobileDashboard
```

Termux上では次の形式を使用する。

```text
$HOME/CodexMobileDashboard
```

共有ストレージではなくTermuxのアプリ専用領域に配置されており、サーバー実行環境として適切である。

## Python互換性

作業用PCではPython 3.10.6、基準端末の検証用Android端末ではPython 3.14.6を使用する。

実装では次を守る。

- Python 3.10以上で利用できる構文と標準ライブラリを使用する。
- Python 3.11以降で追加された機能に依存しない。
- PCのPython 3.10.6と基準端末のPython 3.14.6の両方でテストする。
- Python 3.14で削除された古い非推奨APIに依存しない。
- 外部Pythonライブラリは使用しない。

## Git

Git 2.55.0が利用できることを確認した。基準端末側の配置先ディレクトリがGitリポジトリであることはまだ確認していない。配置方法を決定した後に、必要に応じてcloneまたは同期を行う。

## ストレージ

空き容量は79GBであり、静的ファイル、JSON、直近7日分のローテーションログを保存するMVP用途には十分である。

Codexセッション履歴は容量を理由に自動削除せず、運用ログは日単位でローテーションして直近7日分を保存する。空き容量不足時は過去データを自動削除せず、新規保存を停止して警告する。

## 今後の端末設定

サーバーの常時稼働を開始する前に、次を確認する。

- TermuxをAndroid端末のバッテリー最適化またはスリープ対象から除外する。設定名称はメーカーによって異なる。
- Termux:Bootを使用する場合はTermux本体と同じ配布元から導入する。
- 手動起動とLAN内通信を確認してから自動起動を設定する。
- 必要な場合だけ`termux-wake-lock`を使用する。

## 結論

検証用Android端末のTermux環境は、Codex Mobile DashboardのMVP基準端末として利用可能である。他のAndroid端末は、本書の対象条件と端末固有の省電力・ネットワーク設定を個別に確認する。
