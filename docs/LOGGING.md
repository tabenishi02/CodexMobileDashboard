# ログ出力仕様

## 採用方式

コンソール出力と、日単位でローテーションするテキストファイルを併用する。

Python標準ライブラリの`logging`と`logging.handlers.TimedRotatingFileHandler`を使用し、外部ライブラリには依存しない。

## ログの分離

コンポーネントごとにログファイルを分ける。

| コンポーネント | ログファイル | 内容 |
| --- | --- | --- |
| `collector` | `logs/collector.log` | Codexセッションの検出と読み取り |
| `converter` | `logs/converter.log` | ダッシュボードJSONの生成 |
| `sender` | `logs/sender.log` | Android端末へのHTTP送信 |
| `server` | `logs/server.log` | HTTP受付と静的ファイル配信 |

## 出力形式

1行を1イベントとし、次の順序で出力する。

```text
日時 レベル コンポーネント イベント メッセージ
```

日時はタイムゾーン付きISO 8601形式とする。

```text
2026-08-03T20:15:30+09:00 INFO collector session_scanned records=173
2026-08-03T20:15:31+09:00 INFO sender upload_completed status=200
2026-08-03T20:15:35+09:00 ERROR sender upload_failed error=connection_timeout
```

## ログレベル

| レベル | 用途 |
| --- | --- |
| `DEBUG` | 開発時の詳細情報。通常運用では無効にする |
| `INFO` | 起動、停止、処理完了、送信成功などの通常イベント |
| `WARNING` | 再試行、不完全なJSONL最終行、古いデータなど処理継続可能な問題 |
| `ERROR` | 読み取り失敗、変換失敗、送信失敗、保存失敗など処理が完了できない問題 |
| `CRITICAL` | サーバーを継続できない設定不備や保存領域の重大障害 |

通常運用では`INFO`以上を記録する。

## ローテーション

- 毎日午前0時に新しいログへ切り替える。
- 直近7日分を保存する。
- 文字コードはUTF-8とする。
- ログディレクトリがない場合は起動時に作成する。
- ローテーション失敗で主要処理を停止させない。

## 例外

- `ERROR`以上では例外の種類とスタックトレースを記録する。
- 利用者向けメッセージと技術的な例外情報を区別する。
- 同一エラーの無制限な繰り返し出力を避ける。

## 記録禁止情報

次の情報はログへ記録しない。

- APIキー
- 認証トークン
- パスワード
- 秘密鍵
- 環境変数の全内容
- `auth.json`の内容
- HTTPリクエストの認証ヘッダー
- チャット本文の全文
- コードの全文
- ツール引数とツール出力の全文
- Android端末へ送信するJSONの全文

必要な場合は、件数、サイズ、識別子、処理結果だけを記録する。

## HTTPログ

HTTPアクセスでは次の情報だけを記録する。

- 日時
- HTTPメソッド
- パス
- ステータスコード
- 処理時間
- リクエストサイズ
- 認証の成功または失敗

リクエスト本文と認証情報は記録しない。

## 運用

- PC側とAndroid端末側のログはそれぞれの端末内に保存する。
- ログファイルはGitへ登録しない。
- 障害調査でログを共有する前に秘密情報がないことを確認する。
- 将来、検索や集計が必要になった場合はJSON Lines形式への移行を検討する。
