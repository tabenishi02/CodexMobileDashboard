# データ量と送信対象

## 基本方針

- Codex JSONLから抽出対象としたテキストは、件数、文字数、保存期間を理由に削除または省略しない。
- データ量の制限は保存内容を削るためではなく、通信と画面表示を安定させるための分割基準とする。
- 分割判定は文字数ではなく、JSON生成後のUTF-8バイト数で行う。
- Androidサーバー端末の容量不足時は古いデータを自動削除せず、新規保存を停止して警告する。

## 分割基準

| 対象 | 基準 |
|---|---:|
| 1データ断片 | 最大256KiB |
| 1 HTTPリクエスト | 最大1MiB |
| 通常の送信打ち切り目安 | 約800KiB |
| メッセージ一覧の1ページ | 100件または512KiBの早い方 |
| 初期表示する最近のメッセージ | 50件または512KiBの早い方 |
| ダッシュボード初期データ | 128KiB以内を目安 |

単一メッセージが256KiBを超える場合は複数断片に分割し、メッセージID、断片番号、総断片数、元のバイト数、検証用ハッシュを保持して元の内容を復元できるようにする。

## Gitから送信する情報

GitからAndroidサーバー端末へ送信するのは次のメタデータだけとする。

- ファイルパス
- 追加、変更、削除、名前変更、競合、未追跡の状態
- ステージ状態と作業ツリー状態
- 追加行数と削除行数
- 名前変更前後のパス
- バイナリファイル判定
- ブランチ、`HEAD`、最新コミットの識別情報
- 収集日時と収集エラー

次のデータは送信しない。

- プロジェクトのファイル本体
- ソースコード本文
- Git差分本文
- 画像、動画、音声、PDFなどのファイル本体
- GitリポジトリやGitオブジェクト

未追跡ファイルは内容を読み取らないため、行数とバイナリ判定を未調査として`null`にする。空の追跡済みテキストファイルはGitの測定結果0行として区別する。

Codex JSONLの会話またはツール出力にコードがテキストとして記録されている場合は、セッション履歴の一部として送信対象に含める。PC上のプロジェクトファイルを改めて読み取り、コピーして送る処理は行わない。

## 変更内容の要約

変更内容の意味を表す要約はCodexセッションから生成する。Git差分本文をPC側で解析して要約する処理は実装しない。

- Git：実際の変更ファイルと変更状態を示す。
- Codex JSONL：作業の目的、理由、決定事項、次の作業を示す。

Gitの状態とCodexセッションの説明が一致しない場合は、推測で統合せず別々の情報として表示する。

## PCとAndroidサーバー端末の責務

作業用PCは、Codex JSONLとGitメタデータの収集、解析、分類、要約、JSON生成、分割、送信を担当する。

Androidサーバー端末は、認証、リクエストサイズとJSON形式の検証、安全な保存、静的ファイルとJSONの配信、運用ログ、保存容量監視だけを担当する。Codex JSONL、Git、プロジェクトファイルの解析や表示データの整形は行わない。

更新間隔、ハートビート、ブラウザの自動更新、各データの保存期間は`UPDATE_POLICY.md`に定める。
