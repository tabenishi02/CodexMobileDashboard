# エラー処理仕様

## 基本方針

エラーを開発エラーとシステム運用エラーに分離する。

- 開発エラーは`errors.json`へ保存し、スマートフォンで閲覧できるようにする。
- システム運用エラーは各コンポーネントのローテーションログへ保存する。
- Androidサーバー端末側の詳細エラーを作業用PCへ逆送しない。
- スマートフォンにはシステム状態の要約だけを表示する。

## 開発エラー

### 収集方式

明示的な失敗を基本とし、限定的に既知形式を解析する。

明示的な失敗：

- コマンドの終了コードが`0`以外である。
- `patch_apply_end.success`が`false`である。
- ツールまたは関数呼び出しが明示的な失敗状態を返す。
- Python例外が発生する。

限定的な詳細解析：

- Python Tracebackから例外名、プロジェクト内のファイルパス、行番号を抽出する。
- `unittest`の失敗数と失敗テスト名を、安定して判定できる範囲で抽出する。
- Gitの`fatal`出力は、Gitコマンドの終了コードが`0`以外の場合だけ解析する。

`error`、`failed`などのキーワードだけではエラーと判定しない。標準エラー出力に内容があっても、終了コードが`0`なら原則として警告候補とする。

### 予想される開発エラー

- コマンド失敗
- Python例外
- テスト失敗
- Git未導入、非Git、初回コミットなし
- Gitの`dubious ownership`
- Gitのロック、競合、タイムアウト、履歴変更
- パッチ適用失敗
- タスクの中断またはキャンセル

Gitの所有権設定、ロックファイル削除、履歴変更は自動修正しない。原因と必要な確認事項を表示する。

### 重複と解決

次の情報を正規化してSHA-256フィンガープリントを生成する。

- プロジェクト
- セッションID
- 情報源
- エラー種別
- コマンドまたは処理名
- プロジェクト相対ファイルパス
- 行番号
- 要約

同じフィンガープリントは1件にまとめ、初回発生日時、最終発生日時、発生回数を保持する。

同じコマンド、テスト、パッチ、送信処理が後続処理で成功した場合に解決済みとする。セッション終了だけでは自動的に解決済みにしない。

コマンドはツール名、作業場所、秘密情報除外済みの処理識別情報、テストはテストクラスとテスト名、パッチは並び順を正規化した対象ファイル集合、Python例外は例外名、プロジェクト相対パス、行番号で同一性を判定する。マスク前のコマンド文字列やそのハッシュは保存しない。同じ処理だと明確に判定できない場合は`open`のまま保持し、別のツール実行の成功だけで解決済みにしない。

秘密情報除外処理と接続するまでは、コマンドの処理識別情報を永続化せず、呼び出しIDが異なる失敗を自動的に重複統合・解決しない。パッチの対象ファイル集合など、安全なメタデータだけで同一性を判定できるものは自動解決できる。

`open`は未解決または解決を確認できない状態、`resolved`は同じ処理の後続成功を確認した状態、`ignored`はユーザーが対応不要と判断した状態を表す。`open`であっても自動的な再実行やファイル修正は行わない。

### 件数と本文制限

- `errors.json`の物理ページは最大100件とする。
- 未解決エラーを先に表示するが、古い解決済みエラーも削除せず後続ページに保持する。
- 要約は最大500文字とする。
- 詳細プレビューは最大4,000文字とする。
- 全文が`messages`データに存在する場合は元メッセージを参照し、`errors.json`へ重複保存しない。
- 全文がメッセージに存在しない場合は、必要に応じて断片化して欠落なく保存する。
- 生のコマンド出力全文は`errors.json`へ複製せず、対象となるセッションメッセージを参照する。

安定して分離できる`stderr`、Python Traceback、個別テスト失敗、非ゼロ終了時のGit `fatal`はエラー部分を抽出する。正常な標準出力と安全に分離できない場合は最大4,000文字のプレビューと元JSONL位置だけを保持し、複合出力全文を送信しない。抽出したエラー詳細はメモリ内で秘密情報を除外してから表示用JSONへ変換する。

`turn_aborted`の`interrupted`は`warning`、パッチ失敗と非ゼロ終了コードは`error`とする。終了コード0の標準エラーは原則として登録せず、Tracebackまたはテスト失敗を既知形式で確認できる場合だけ`warning`にする。`incomplete`ターンは開発エラーへ重複登録しない。ロールバック済みターンのエラーは履歴に保持するが、現在の未解決件数には加算しない。

発生日時はJSONLレコード日時、セッションファイル更新日時の順で使用し、どちらも取得できなければ`null`と取得元`missing`を保持する。現在時刻では補完しない。

## セッション収集エラー

### 書き込み途中の最終行

正常に発生し得る状態として扱う。不完全な最終行を保持し、次回読み取り時に続きから再解析する。

### JSONL途中の不正な行

その行だけを除外し、後続行の処理を継続する。ファイルパス、行番号、失敗種別だけをログへ記録する。

### 未知のイベント

エラーにせず、未知の`type`を警告として記録して無視する。

### セッションファイルの移動

`sessions`で見つからない場合は`archived_sessions`を確認し、セッションIDで追跡する。

### 読み取り位置の無効化

現在のファイルサイズが保存済みオフセット未満なら先頭から再解析し、フィンガープリントで重複を除外する。

## HTTP送信エラー

### 指数バックオフ

一時的な失敗では、初回送信を含む`max_attempts`回まで再試行する。既定値は5回で、待機時間は次のとおりである。

```text
1秒 → 2秒 → 4秒 → 8秒
```

成功した場合は失敗回数をリセットする。既定5回がすべて失敗した後は短時間の再試行を終了し、次回の定期Collector実行へ持ち越す。v0.1.0の既定周期は1分である。

送信に失敗したSnapshotは、Androidサーバー端末がcommit成功を返すまでPC側の永続キューに本文複製、送信順序、各Delivery IDとともに保持する。新しいJSONが生成されても未送信Snapshotを破棄せず、順次再送する。Androidサーバー端末側では同じ識別子の再送を重複保存しない。

再試行するエラー：

- 接続拒否
- 接続タイムアウト
- HTTP 408
- HTTP 429
- HTTP 500番台

HTTP 429に`Retry-After`がある場合は、その指定を優先する。

自動再試行しないエラー：

- HTTP 400：送信データを隔離し、次の正常なJSON生成を待つ。
- HTTP 401または403：再試行を停止し、認証設定の確認を要求する。
- HTTP 413：件数や本文を制限してJSONを再生成する。

## Androidサーバー端末のエラー

Androidサーバー端末内部で発生した詳細エラーは端末側の`logs/server.log`へ保存する。

作業用PCは、PCから観測できたHTTPステータス、タイムアウト、接続失敗だけを`logs/sender.log`へ保存する。Androidサーバー端末のログやスタックトレースをPCへ逆送しない。

| エラー | Androidサーバー端末側の対応 |
| --- | --- |
| 認証失敗 | HTTP 401を返し、秘密値を記録しない |
| 不正JSON | HTTP 400を返し、既存JSONを維持する |
| サイズ超過 | HTTP 413を返し、本文を保存しない |
| ディスク容量不足 | HTTP 507を返し、既存JSONを維持する |
| 保存失敗 | HTTP 500を返し、一時ファイルを破棄する |
| ポート使用中 | 起動を中止し、別ポートへ自動変更しない |

JSON保存では一時ファイルへ書き込み、完了後に`os.replace()`で置換する。

## ブラウザ表示エラー

- JSON取得失敗時は最後の正常画面を維持する。
- 不正JSONを画面へ反映しない。
- データが古い場合はエラーではなく警告として表示する。
- メッセージ、コード、エラーは`innerHTML`へ直接代入せず、原則として`textContent`で表示する。
- 自動更新に失敗しても次回更新を継続する。

## スマートフォンのシステム状態表示

詳細な運用ログではなく、次の要約だけを表示する。

- 最終送信成功日時
- 連続送信失敗回数
- 最新の送信結果
- 保存データの最終更新日時
- データが古い場合の警告

スタックトレース、秘密情報、認証ヘッダー、HTTP本文は表示しない。

## 重要度

| 重要度 | 意味 | 例 |
| --- | --- | --- |
| `info` | 正常な補足情報 | 再接続成功 |
| `warning` | 処理を継続できる問題 | 不完全なJSONL最終行 |
| `error` | 個別処理を完了できない問題 | コマンド失敗、HTTP送信失敗 |
| `critical` | システムを継続できない問題 | 設定不備、保存不能、Git未導入 |

## 保存場所

| 情報 | 保存場所 |
| --- | --- |
| 開発エラー | PC側の`errors.json` |
| セッション収集エラー | PC側の`logs/collector.log` |
| JSON変換エラー | PC側の`logs/converter.log` |
| HTTP送信エラー | PC側の`logs/sender.log` |
| Androidサーバー端末内部エラー | 端末側の`logs/server.log` |
| ブラウザ表示エラー | 画面上の要約とブラウザコンソール |
