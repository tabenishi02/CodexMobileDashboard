# Phase 5 画面構成設計

## 目的と前提

本書はスマートフォン向け閲覧画面の情報構造と遷移を定義する。画面は読み取り専用であり、Codex、Git、Androidサーバーの設定を操作しない。HTML、CSS、JavaScriptの実装時は本書と`DATA_SCHEMA.md`を正とする。

閲覧URLは`/?workspace_id=<workspace_id>`とする。`workspace_id`が未指定の場合はデータを取得せず、URLへの指定方法だけを案内する。画面側でIDを推測、列挙、保存しない。

## 全体構成

1つの固定HTML内で画面を切り替える。初期画面はダッシュボードとし、ブラウザの戻る・進む操作に対応するため画面名はフラグメント（例：`#chat`）で表す。フラグメントはクライアント内の表示状態だけを示し、`workspace_id`は常にURLクエリを正とする。

```text
共通ヘッダー
├─ プロジェクト名、Phase、Codex状態
├─ 最終更新表示、更新中表示、手動更新
└─ 通信・古さの状態

主画面
├─ ダッシュボード       #dashboard
├─ 最近の更新           #recent
├─ チャット             #chat
├─ エラー               #errors
├─ 決定事項             #decisions
├─ ファイル             #files
└─ システム情報         #system

固定ナビゲーション（画面下部）
├─ ダッシュボード
├─ 最近の更新
├─ チャット
├─ エラー
└─ その他（決定事項、ファイル、システム情報）
```

縦画面では下部ナビゲーションの主要5項目を常時表示し、「その他」は同じ画面内の選択肢から残り3画面へ遷移する。現在画面は文字とアイコンで明示し、色だけで区別しない。画面内容の上端には画面名を表示する。

## 初期取得と画面別取得

初回表示では`dashboard.json`、`metadata.json`、`/health?workspace_id=<workspace_id>`を取得する。これにより概要、PC収集状態、Androidサーバー状態を最小の通信量で示す。`recent.json`、`messages.json`、`errors.json`、`decisions.json`、`files.json`は、各画面を最初に開く時だけ取得する。画面を再訪した場合はETagで更新確認を行う。

会話ページ、会話断片、変更要約ページ、エラー断片は、それらを参照する詳細を開いた場合だけ取得する。画面は一覧や本文を独自に要約・再分類しない。

| 画面 | 初回データ | 遅延データ | 主な遷移先 |
|---|---|---|---|
| ダッシュボード | `dashboard.json`、`metadata.json`、`/health` | なし | 最近の更新、チャット、エラー、ファイル、システム情報 |
| 最近の更新 | `recent.json` | 関連メッセージのページ | チャット |
| チャット | `messages.json` | `messages/pages/`、`messages/chunks/` | なし |
| エラー | `errors.json` | `messages/`、エラー断片 | チャット |
| 決定事項 | `decisions.json` | 関連メッセージのページ | チャット |
| ファイル | `files.json` | なし | なし |
| システム情報 | `metadata.json`、`/health` | なし | なし |

## 各画面

### ダッシュボード

最優先の確認画面とする。上からプロジェクト名・Phase、Codex状態と現在作業、最新の変更要約、次に行う作業、未解決エラー件数、Git変更件数とブランチ、PC生成日時を表示する。各要約カードには該当する詳細画面へのリンクを置く。最新ユーザー指示・Codex回答は、`dashboard.json`の参照IDだけでは本文を確定できないため、この画面では`latest.summary`を表示し、全文はチャット画面で表示する。

Phaseはworkspace固有の明示情報だけを使用し、collector側で固定値や推測値を補完しない。明示情報がない場合は`dashboard.json`の`project.phase`を`null`とし、画面では「Phase: 情報なし」と表示する。

次タスクのfallbackは対象workspace直下の`TASKS.md`だけを参照する。対象workspaceにファイルがない場合は`dashboard.json`の`next_actions`を空配列とし、画面では「データがありません（次の作業）。」と表示する。他workspaceやcollector起動ディレクトリのタスクは表示しない。

collector統合テストでは、異なる`TASKS.md`を持つ複数workspaceを連続して処理し、プロジェクト名、`project.phase`、fallback次タスク、タスクIDがworkspace間で混入しないことを検証する。

### 最近の更新

`recent.json`の`current_turn`を先頭に、完了済み`turns`を新しい順に表示する。各項目には状態、開始・完了日時、ユーザーとCodexのプレビュー、ロールバック状態を示す。プレビューを本文として扱わず、詳細操作は該当メッセージを表示できるチャット画面へ遷移する。

### チャット

`messages.json`のページ索引を使い、メッセージをページ単位で時系列に表示する。最初は最新ページを取得し、前のページは利用者が「以前のメッセージを読み込む」を選んだ時だけ取得する。ユーザー、Codex、開発者指示は役割ラベルと構造で区別し、各メッセージの`created_at`を共通JST形式で表示する。`display_mode: collapsed`、長文、コードブロックは折りたたみ、展開時に必要な断片だけを順番に取得して復元する。Markdownは`markdown-it`で安全なサブセットを表示し、HTML入力は無効化したうえでDOMPurifyによりサニタイズする。見出し、リスト、引用、リンク、インラインコード、コードブロックを対象とし、コードはhighlight.jsで強調する。ライブラリが利用できない場合はプレーンテキストへフォールバックし、画像や任意HTMLの実行は許可しない。

### エラー

`errors.json`から未解決を先に、解決済み・無視を後に表示する。各項目は重要度、状態、要約、発生日時、発生回数を示す。詳細は折りたたみ、`details_preview`、`details`、`detail_chunks`、`source_message_ids`の種別に従って表示する。元メッセージを開く操作はチャット画面へ遷移する。Androidサーバーの内部エラー詳細は表示しない。

### 決定事項

`decisions.json`の履歴を新しい順に表示する。表題、状態、決定日時、内容、理由、置換前後の関係を示す。根拠メッセージがあればチャットへ遷移する。過去の`superseded`を削除・上書きしない。

### ファイル

`files.json`のGitメタデータだけを表示する。上部にリポジトリ名、ブランチ、HEAD、取得状態、作業ツリー状態を置き、一覧にはパス、状態、追加・削除行数、ステージ状態、名前変更元、バイナリ判定を表示する。ファイル本文、Git差分本文、画像などの内容を取得・表示しない。

### システム情報

PC collectorとAndroidサーバーの状態を分けて表示する。PC側は`metadata.json`からcollector状態、Codex状態、最終確認日時、最終データ変更日時、前回送信成功日時を表示する。Android側は`/health?workspace_id=<workspace_id>`から状態、稼働秒数、public・staging・ログ・容量の利用可否、公開中Snapshot ID、最終受信日時を表示する。`current_snapshot_id`と`last_received_at`が`null`の場合は「公開済みデータなし」または「日時未記録」と表示し、推測で補完しない。

システム情報画面への遷移時は、初期取得で保持した`metadata.json`とworkspace指定付き`/health`を描画に再利用し、画面遷移だけを理由とする追加通信は行わない。初期取得中に遷移した場合は読込中表示を維持し、取得完了後に表示中のシステム情報画面を再描画して読込中表示を終了する。システム情報画面を表示したまま初期データを更新した場合も、更新完了後に同じ再描画を行う。

クライアント回帰テストでは、公開中Snapshot IDと最終受信日時がある状態、両方が`null`の未公開状態、`/health`取得失敗を別シナリオとして検証する。未公開状態を通信失敗として表示せず、通信失敗を「公開済みデータなし」として表示しない。

## 共通の表示状態

データ文書ごとに、読み込み中、データなし、不正データ、通信失敗、古いデータを独立して表示する。ある文書の失敗で他画面を停止しない。更新中はヘッダーへ表示するが、既に表示済みの正常データは消さない。

古さは`metadata.json`の`collector.last_checked_at`、`collector.last_data_change_at`、`collector.last_send_succeeded_at`と、`/health`の`last_received_at`を別々に表示して判断する。閾値や文言は実装タスクで定め、現在時刻や失敗時刻をデータ日時として代用しない。

JSON内のUTCを含むタイムゾーン付きISO 8601値は変更せず、ブラウザの共通日時整形でだけ`Asia/Tokyo`へ変換し、`YYYY/MM/DD HH:mm:ss JST`形式で表示する。JSON文書や`/health`応答をJSTへ書き換えない。

共通日時整形は、ヘッダー最終更新、ダッシュボードのデータ生成日時、最近の更新の開始・完了日時、チャットの作成日時、エラー発生日時、決定日時、PC collectorの各日時、Androidサーバーの最終受信日時へ適用する。

クライアント回帰テストでは、UTCからJSTへの変換で日付が翌日に繰り上がる境界を含め、日付と時刻の両方が`Asia/Tokyo`として表示されることを検証する。

## 安全性と表示規則

JSON由来文字列は`textContent`相当の方法で表示し、`innerHTML`へ渡さない。外部ライブラリ、外部スクリプト、外部スタイル、ブラウザ保存領域を使用しない。トークン、サーバー内部パス、Traceback、HTTP本文は表示しない。画面で必要な日本語ラベルへの変換は`DATA_SCHEMA.md`の列挙値を使用する。
