# Phase 8.1 ワークスペース選択・閲覧UI整理 設計書

## 1. 目的

Phase 5で実装したスマートフォン向け閲覧画面について、通常利用時に内部の`workspace_id`を利用者が把握する必要をなくし、共通ヘッダーと更新状態表示を簡素化する。

本変更では次を行う。

1. Androidサーバーが現在公開しているワークスペースをトップページから選択できるようにする。
2. ワークスペース画面の共通ヘッダーを「プロジェクト名」と「最終更新日時」だけにする。
3. Codex状態と手動更新操作を「その他 → システム情報」へ集約する。
4. 正常取得後に「初期データを取得しました。」が常時残る表示を廃止する。
5. 既存の`/?workspace_id=<workspace_id>`直接URLは互換性のため維持する。

Phase 9の外部アクセスとは独立した、MVP完了前の閲覧UI改善として扱う。

## 2. 現状

現在の閲覧URLは次の形式である。

```text
/?workspace_id=<workspace_id>
```

`workspace_id`がない場合、クライアントはデータを取得せず、IDをURLへ指定する案内だけを表示する。したがって利用者はPC側の生成データや既存ブックマークからIDを確認する必要がある。

共通ヘッダーには現在、次が表示される。

- 固定表示「Codex Mobile Dashboard」
- プロジェクト名
- Phase
- Codex状態
- 更新状態・最終更新日時
- 更新ボタン

また、初期データ取得成功後はグローバル状態表示が「初期データを取得しました。」のまま残る。15秒間隔の自動更新も同じ`initialize()`を利用しているため、この成功表示が通常時にも常設される。

## 3. 変更後の画面構成

### 3.1 トップページ

`workspace_id`を指定せずに`/`を開いた場合は、ワークスペース選択画面を表示する。

```text
ワークスペースを選択

┌─────────────────────────────┐
│ CodexMobileDashboard        │
│ 最終更新 2026/09/29 ... JST │
└─────────────────────────────┘

┌─────────────────────────────┐
│ NumpadWindowController      │
│ 最終更新 2026/09/29 ... JST │
└─────────────────────────────┘
```

各項目を選択すると、既存形式のURLへ遷移する。

```text
/?workspace_id=<workspace_id>
```

利用者へ`workspace_id`の入力を要求しない。通常の一覧画面ではID自体を主情報として表示しない。

トップページではワークスペース固有の下部ナビゲーションを表示しない。

### 3.2 ワークスペース画面の共通ヘッダー

共通ヘッダーに残す情報は次の2点だけとする。

- ワークスペース＝プロジェクト名
- 最終更新日時

表示例:

```text
CodexMobileDashboard
最終更新: 2026/09/29 15:58:20 JST
```

次は共通ヘッダーから削除する。

- 固定表示「Codex Mobile Dashboard」
- Phase
- Codex状態
- 更新状態
- 更新ボタン

ブラウザの`<title>`はページ識別用のメタデータであり、画面上の固定表示ではないため、`Codex Mobile Dashboard`のまま維持してよい。

### 3.3 システム情報

「その他 → システム情報」に更新操作を追加し、運用状態を集約する。

```text
システム情報

更新
  [ 更新 ]
  更新状態: 更新しました / 更新中 / 一部取得失敗

PC収集ツール
  収集状態
  Codex状態
  最終確認日時
  最終データ変更日時
  前回送信成功日時

Androidサーバー
  サーバー状態
  ...
```

Codex状態は既存の`metadata.json`の`collector.codex_status`を使用する。共通ヘッダーの`dashboard.codex.status`表示は削除する。現在作業はダッシュボードの「現在の作業」カードに残す。

更新ボタンは現在の初期3文書再取得処理を引き続き使用し、場所だけをシステム情報画面へ移す。

## 4. ワークスペース一覧取得

### 4.1 読み取り専用エンドポイント

Androidサーバーへ次の読み取り専用GETを追加する。

```text
GET /workspaces
```

既存の閲覧用`/health`・`/data/`と同様、閲覧スマートフォンから利用するGETとする。Snapshot送信用Bearer Tokenは要求しない。

`/api/`配下は現在、認証付きSnapshot書き込みAPIとして扱っているため、今回の閲覧用一覧は`/workspaces`として分離する。

応答例:

```json
{
  "workspaces": [
    {
      "workspace_id": "workspace-xxxxxxxx",
      "project_name": "CodexMobileDashboard",
      "last_received_at": "2026-09-29T06:58:20+00:00"
    }
  ]
}
```

返す情報は次に限定する。

- `workspace_id`
- `project_name`
- `last_received_at`

内部パス、staging情報、過去Snapshot ID、Token、その他のサーバー内部情報は返さない。

### 4.2 一覧対象

単にディレクトリが存在するだけでは一覧へ掲載しない。

次の条件をすべて満たすワークスペースだけを掲載する。

1. public直下のディレクトリ名が既存のworkspace識別子規則に一致する。
2. 有効な`current.json`が存在する。
3. `current.json`が参照するSnapshotディレクトリが存在する。
4. そのSnapshotの`dashboard.json`がUTF-8 JSONとして読み取れる。
5. `dashboard.json`の`workspace_id`と`snapshot_id`がcurrent参照先と一致する。
6. `dashboard.project.name`が空でない文字列である。

staging中、未commit、壊れたcurrent、欠損したdashboard、識別情報が不一致のデータは一覧から除外する。1件の不正データで一覧全体を失敗させない。

### 4.3 並び順

一覧はプロジェクト名の昇順とし、同名の場合は`workspace_id`を第2キーにして安定した順序にする。

### 4.4 キャッシュ

`/workspaces`は応答JSONからETagを生成し、`If-None-Match`に対して`304 Not Modified`を返せるようにする。

## 5. クライアント状態

### 5.1 workspace_id未指定

従来の「workspace_idを指定してください」画面を廃止し、次の状態を持つワークスペース一覧へ置き換える。

- 読み込み中
- 一覧あり
- 公開中ワークスペースなし
- 一覧取得失敗

一覧取得失敗時にIDの手入力を要求しない。既知の直接URLは引き続き利用できる。

### 5.2 workspace_id指定済み

既存のダッシュボード初期化を維持する。

```text
dashboard.json
metadata.json
/health?workspace_id=<workspace_id>
```

既存ブックマークとの互換性を維持し、URL形式を変更しない。

## 6. 更新状態表示

グローバル状態表示は「正常であることを常時通知する領域」ではなく、読み込み中または異常時の通知に限定する。

### 6.1 初回取得

初回取得中:

```text
初期データを読み込んでいます。
```

初回取得成功後:

- グローバル成功メッセージを非表示にする。
- 「初期データを取得しました。」を常設しない。

一部失敗:

```text
一部の初期データを取得できませんでした。
```

### 6.2 自動更新

15秒間隔の自動更新は維持する。

正常な自動更新ではグローバル成功メッセージを表示しない。既存表示内容を維持しながらバックグラウンドで更新する。

失敗時は既存の正常データを消さず、異常状態を表示する。

### 6.3 手動更新

システム情報画面の更新操作では、更新ボタン付近に次を表示する。

- `更新中`
- `更新しました`
- `一部の取得に失敗`

これはシステム情報画面内の操作結果表示であり、全画面共通の成功通知にはしない。

## 7. Phase情報

画面上のPhase表示は削除する。

ただし、互換性維持のため`dashboard.json`の`project.phase`フィールドやcollector側のPhase抽出処理は、このPhaseでは削除しない。今回の変更対象は表示だけとする。

将来データスキーマから削除する場合は、別途スキーマ互換性変更として扱う。

## 8. HTML・JavaScript変更方針

主な変更対象は次のとおり。

### client/index.html

- 固定の`Codex Mobile Dashboard`表示を削除する。
- Phase表示領域を削除する。
- 共通Codex状態を削除する。
- 共通更新状態・更新ボタンを削除する。
- 共通ヘッダーへプロジェクト名と最終更新日時だけを残す。
- workspace未指定用の一覧領域を追加する。
- システム情報画面へ更新ボタンと更新状態領域を追加する。

### client/app.js

- workspace未指定時に`/workspaces`を取得する。
- 一覧項目を安全なDOM操作で生成する。
- 選択リンクを`/?workspace_id=<encoded id>`として生成する。
- Phase描画を停止する。
- 共通Codex状態描画を停止する。
- ヘッダー最終更新日時だけを更新する。
- 正常取得後の`global-status`を非表示にする。
- 更新ボタンと更新状態をシステム情報画面へ移す。
- 現在重複登録されている`visibilitychange`イベントリスナーを1回に修正する。

### client/styles.css

- 一覧カードのスマートフォン向けスタイルを追加する。
- 簡素化したヘッダーに合わせて不要なレイアウトを削除・整理する。
- 一覧項目全体を十分なタップ領域として扱う。

## 9. Androidサーバー変更方針

### server/server.py

- `GET /workspaces`を追加する。
- public領域を安全に走査し、currentと現在Snapshotのdashboardだけを参照する。
- 不正なworkspaceを個別にスキップする。
- 応答へETagを付与する。
- 一覧取得のためにstagingや過去Snapshotを公開しない。
- 一覧生成時にプロジェクトファイル、Git差分、秘密情報を読み取らない。

SnapshotのPOST・commit契約には変更を加えない。

## 10. 安全性

- ワークスペース一覧はcommit済みpublic Snapshotだけを情報源にする。
- HTMLへ文字列を直接挿入せず、通常表示は`textContent`相当を使用する。
- workspaceリンクは`encodeURIComponent()`相当でIDをエンコードする。
- 一覧APIでファイルパス、内部ディレクトリ、Token、証明書情報を返さない。
- 不正なworkspaceディレクトリ名、current参照、dashboard識別情報を信用しない。
- 既存のHTTPS必須方針を変更しない。

## 11. テスト

### 11.1 サーバーテスト

少なくとも次を追加する。

- 有効な複数workspaceを一覧取得できる。
- project名と最終受信日時が返る。
- currentがないworkspaceを除外する。
- currentが壊れているworkspaceを除外する。
- current Snapshotにdashboardがないworkspaceを除外する。
- dashboardのworkspace/snapshot識別情報不一致を除外する。
- 未commitのstagingだけのworkspaceを掲載しない。
- 危険なディレクトリ名を掲載しない。
- 1件の不正workspaceが他の正常workspace一覧を壊さない。
- ETagと304が動作する。
- 一覧応答に内部パス・Token・過去Snapshot情報を含めない。

### 11.2 クライアントテスト

少なくとも次を追加・更新する。

- `workspace_id`なしでワークスペース一覧を取得する。
- 一覧からプロジェクト名を表示する。
- 選択リンクが既存の`/?workspace_id=...`形式になる。
- 空一覧を正常状態として表示する。
- 一覧取得失敗を空一覧と区別する。
- `workspace_id`指定済みでは従来どおりダッシュボードを開く。
- 共通ヘッダーにプロジェクト名と最終更新日時だけが表示される。
- 固定タイトル・Phase・Codex状態・更新ボタンが共通ヘッダーにない。
- Codex状態と更新ボタンがシステム情報に表示される。
- 正常取得後に「初期データを取得しました。」が常設されない。
- 一部取得失敗時は警告が表示される。
- 15秒自動更新と画面復帰時更新を維持する。
- `visibilitychange`リスナーが重複登録されない。

## 13. 実機受入条件

Phase 8.1完了には、CA信頼済みの閲覧スマートフォンで次を確認する。

1. `/`だけでトップページを開ける。
2. Androidサーバーが保持する複数の有効workspaceがプロジェクト名で表示される。
3. workspace IDを利用者が調べたり入力したりせず、一覧から対象を開ける。
4. 既存の直接URLも引き続き開ける。
5. 共通ヘッダーがプロジェクト名と最終更新日時だけになる。
6. Codex状態と更新ボタンがシステム情報にある。
7. 更新成功後に「初期データを取得しました。」が常時残らない。
8. 手動更新、自動更新、画面復帰時更新が正常に動作する。
9. 一覧・ダッシュボードともHTTPSで正常表示される。
10. 既存の主要画面とSnapshot表示に回帰がない。

## 14. 非対象

このPhaseでは次を行わない。

- workspaceの作成・削除・名前変更
- 複数workspaceの同時比較
- workspaceのお気に入り・並び替え設定
- ブラウザローカルストレージへの選択履歴保存
- 外部アクセス・Tailscale
- `project.phase`のデータスキーマ削除
- Snapshot送信APIの変更
